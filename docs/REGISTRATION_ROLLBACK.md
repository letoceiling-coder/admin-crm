## 🔄 Логика работы

### Успешная регистрация

```
1. Пользователь заполняет форму
2. POST /api/auth/register
3. Создается пользователь в БД (транзакция)
4. Пользователь авторизуется
5. Отправляется заявка в ADMIN
6. ADMIN возвращает успех (201)
7. Токен сохраняется в CRM settings
8. Редирект в /admin/dashboard ✅
```

### Ошибка при регистрации

```
1. Пользователь заполняет форму
2. POST /api/auth/register
3. Создается пользователь в БД (транзакция)
4. Пользователь авторизуется
5. Отправляется заявка в ADMIN
6. ADMIN возвращает ошибку или не отвечает ❌
7. Выход из сессии (Auth::logout())
8. Инвалидация сессии
9. Выброс ValidationException
10. Откат транзакции → пользователь удаляется
11. Возврат ошибки 422 с деталями
12. Показ SweetAlert2 с рекомендацией попробовать снова
13. Форма очищается (пароли), имя и email сохраняются
14. Пользователь НЕ авторизован → доступ в админ панель ЗАБЛОКИРОВАН ✅
```

## 📚 Технические детали

### Транзакция БД

Согласно [Laravel Database Transactions](https://laravel.com/docs/10.x/database#database-transactions):

```php
DB::transaction(function () {
    // Если внутри функции выброшено исключение
    // все изменения автоматически откатываются
});
```

### ValidationException

Согласно [Laravel Validation](https://laravel.com/docs/10.x/validation#manually-creating-validators):

```php
throw ValidationException::withMessages([
    'admin_api' => ['Сообщение об ошибке'],
]);
```

**Результат**: JSON ответ с кодом 422 и полем `errors.admin_api`
